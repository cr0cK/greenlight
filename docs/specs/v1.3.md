# Greenlight v1.3 specification

## Goal

Show how much of the Claude and Codex subscription quotas is used, next to the pull requests the
agents open, so their use can be spread over the week instead of hitting a limit on Thursday.

## Scope

- Two providers: Claude (Claude Code subscription) and Codex (ChatGPT sign-in). Both are off by
  default. Other agents, API-key billing, and a panel indicator are out of scope.
- Greenlight never asks for a credential. Each provider reuses the sign-in of its own CLI, the
  way pull requests reuse `gh`.

## Preferences

- A new **Agent quotas** group holds:
  - A **Claude** switch and a **Codex** switch. Each subtitle says what the provider reads
    (`Uses the Claude Code sign-in`, `Uses the codex CLI`), or why it cannot be used yet
    (`codex not found in PATH`, `Claude Code is not signed in`).
  - **Refresh every**, in minutes: 15 to 240, default 60.
  - **Notify at**, in percent: 50 to 100, default 80.
- Every row applies on **Save preferences**. A disabled provider reads no file, starts no process,
  and makes no network call.

## Menu

- With at least one provider enabled, an **Agent quotas** section sits right above the pull
  request list, after quick open. Without any, the section is absent.
- Each provider gets one line per quota window it reports, labelled `5 h` or `Week` (any other
  duration is labelled by its length):

  ```text
  Claude  5 h   ███░░|░░░  38 %  resets in 2 h 10 min
          Week  █████░|░░  61 %  resets Fri 14:00
  Codex   Week  █░░░|░░░░  16 %  resets Tue 09:30
  ```

- The bar fills with the used share. A pace mark (`|` above) sits at the elapsed share of the
  window, so a fill past the mark means the quota runs out before it resets. The bar takes the
  warning color at or above **Notify at**, and the error color at 100 %.
- A reset under a day away reads as a duration; later ones as a weekday and time.
- A dimmed `Updated 12 min ago` line closes the section.
- **Refresh now** refreshes the quotas along with the pull requests. Opening the menu refreshes
  them when the last reading is more than 5 minutes old; otherwise they follow their own timer,
  independent of `refresh-interval`.

## Notifications

- When a window crosses **Notify at** between two readings, a notification names the provider,
  the window, the percentage, and the reset time: `Claude weekly quota at 82 % · resets Fri 14:00`.
- Each window notifies at most once per period: a new `resets_at` starts a new period. The first
  reading after a provider is enabled sets a quiet baseline and never notifies.
- Errors never notify.

## Claude

- Reads `claudeAiOauth.accessToken` and `expiresAt` from `.credentials.json` in
  `$CLAUDE_CONFIG_DIR`, or `~/.claude` when unset. Greenlight never writes that file and never
  uses the refresh token: refreshing rotates it and would sign Claude Code out.
- Calls `GET https://api.anthropic.com/api/oauth/usage` with `Authorization: Bearer <token>` and
  `anthropic-beta: oauth-2025-04-20`, and reads `five_hour` and `seven_day`
  (`utilization`, `resets_at`). Other windows in the answer are ignored.
- An expired token is not sent; the line reads `Open Claude Code to renew its sign-in` until
  Claude Code refreshes the file.
- The endpoint is not documented. An answer without the expected fields reads
  `Claude usage format changed` rather than showing a guess.

## Codex

- Starts `codex app-server` with an argument array, sends `initialize`, `initialized`, then
  `account/rateLimits/read` over stdio JSON-RPC, and stops the process once it answers or after
  15 seconds. Codex handles its own token refresh.
- Reads `primary` and `secondary` (`usedPercent`, `windowDurationMins`, `resetsAt`) and maps them
  to windows by duration. A missing window is not shown; plans without a 5-hour window show only
  `Week`.

## Errors

- A failing provider keeps its last reading, dimmed, with a short cause under it: CLI not found
  in `PATH`, not signed in (`Run codex login`, `Sign in to Claude Code with a subscription`),
  expired token, unreachable host, HTTP status, or changed format. Without any reading, only the
  cause shows.
- One provider failing never hides the other, nor the pull requests.

## Storage and privacy

- New settings: `claude-quota-enabled` and `codex-quota-enabled` (booleans, false),
  `agent-quota-interval` (minutes, 60), `agent-quota-threshold` (percent, 80), and
  `agent-quota-cache` (JSON: last readings, their time, and the periods already notified).
- Tokens stay in memory for one request. They are never stored in settings, logged, or sent
  anywhere but `api.anthropic.com` over HTTPS.
- Parsing, window mapping, pace, threshold crossing, and messages live in a pure `src/quotas.js`
  covered by `node --test`; the extension only reads the file, makes the request, and runs codex.
