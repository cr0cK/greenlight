# Greenlight v1.2 specification

## Goal

Show pull request labels, so a row tells what kind of change it is without opening it.

Watch every repository of an owner except a few, without listing dozens of repositories to keep.

Say what is wrong when gh or an owner cannot be used, instead of a generic refresh failure.

## Pull request rows

- The first line shows the labels right after the `#number` badge, before the title.
- Each label is a badge in its GitHub color. Its text is dark on light colors and white on dark
  ones; a label without a valid color uses the neutral number badge color.
- At most three labels show; the rest collapse into a `+N` badge whose accessible name lists them.
- Long label names ellipsize, so the title keeps its room.
- Labels come from `gh search prs --json labels`, in the same request as the rest of the row.

## Preview

- The preview shows up to six labels under the title, for pull requests as well as issues, in the
  same colors as the rows. They come from the existing preview GraphQL request.

## Quick open

- The quick open placeholder lists the accepted forms: `Open issue or PR: repo #42,
  owner/repo#42, #42 or URL`.

## Preferences

- **Accounts and organizations** holds **Discover accounts** (the gh account and its
  organizations) and **Add an owner**. **Add** checks the login with `gh api users/<login>`
  before listing it and takes its kind (personal account or organization) from the answer; an
  unknown login is refused with a message, other failures explain the gh problem.
- Each owner then gets its own block, titled with its login and described as
  `<kind> · Monitoring|Paused · <scope>`, where the scope reads `All repositories`,
  `All except N repositories`, or `N selected repositories`. Its header has a trash icon that
  removes the owner and a switch that pauses it; both apply on **Save preferences**. A paused
  owner's rows are greyed out.
- A block has three steps:
  1. **Repositories**, with **Discover**: runs `gh repo list` for that owner only, on demand.
  2. **Monitor**: **All** (every repository, including new ones), **All except…** (new
     repositories are monitored; turn off the ones to skip), or **Only…** (only the repositories
     turned on; new ones are skipped). It shows the saved mode, and can only change once the
     repositories are discovered, so a selection is never converted without its list.
  3. A collapsible `M of N monitored` list with a filter and one switch per repository, shown
     for **All except…** and **Only…**. It opens when the mode changes to one of them.
- A repository switch on always means monitored. Changing between **All except…** and **Only…**
  keeps every switch; only the rule for new repositories changes. Leaving **All** turns every
  switch on.
- A block refreshes in place after **Discover**, so the page keeps its scroll position. An added
  owner's block comes first; owners found by **Discover accounts** come last, paused unless they
  are the first ones configured.

## Owner filter settings

- Each owner in `owner-filters` gains `excludedRepositories`, used only when `repositories` is
  null. Settings without it read as no exclusions; a version without this feature ignores it and
  monitors every repository of that owner.

## Search scopes

- An owner with exclusions gets its own `gh search prs` command, with `-repo:owner/name` terms
  after `--`, within the existing query length and qualifier bounds.
- Exclusions that do not fit are filtered from the results on the client only. Because that can
  shorten a full page, the search runs again with a larger limit, up to 1000, until the owner
  yields its share of the 30 most recent pull requests; group and panel counts follow the
  filtered list.

## Pull request previews in the list

- A click on a pull request row toggles its preview under the row and keeps the menu open; only
  one preview exists at a time. Hovering or focusing a row no longer opens anything.
- An open icon at the end of the row's first line, a double click on the row, or a click on its
  preview opens the pull request and closes the menu. With the keyboard, Space toggles the
  preview and Enter opens the pull request.
- After a click, the list waits for the double-click time before scrolling the preview into
  view, so the row stays under the pointer for a second click.
- The wheel over a preview scrolls its description; at either end, or when nothing overflows, it
  scrolls the list instead, so a preview never traps the list scroll.
- The `hover-preview-delay` setting and its **Preview listed pull requests on hover** row are
  gone; the **Quick open and preview** group is now **Quick open**.

## Errors and missing owners

- Before searching, each refresh checks in one `gh api graphql` request that every enabled owner
  (`repositoryOwner`) and every repository of an **Only…** selection (`repository`) still exists
  for gh. Missing ones are left out of the search and listed in a warning row under
  **Refresh now**; the rest are searched as usual. Without this, a search naming only missing
  owners fails as a whole and one naming some of them skips them silently.
- A failed refresh shows an error row under **Refresh now** that names the cause: gh missing from
  `PATH`, gh not signed in (exit code 4, `gh auth login`), GitHub unreachable, the rate limit, or
  gh's own first error line. The panel shows `PR !` and the last pull requests stay listed.
  The shell log line for the failure also carries gh's first error line, so a primary rate limit
  can be told from a secondary one.
